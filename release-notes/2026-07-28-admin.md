Interactive experience — This is a fully interactive prototype. Feel free to click, create, edit, and delete items to test the workflows.
Live updates — The prototype uses realistic sample data. Any changes you make apply live as you navigate between different screens.
Session persistence — Any data you create, edit, or cancel survives a page refresh and tab close. Your demo session sticks until you explicitly reset.

1 Schedule
The schedule grid across upcoming, ongoing, and past classes for owners, admins, and operators.
Capabilities:
Spots column always visible — Spot count is shown consistently on upcoming and past schedules, so capacity reads at a glance whether the class is next week or last month.
Empty rating placeholder — Upcoming classes show a placeholder in the rating column instead of a blank cell, so the table lines up cleanly with completed classes.
Full booking list restored — Every class schedule now shows its complete booked-customer list; earlier a handful of entries were missing.
Flexible tag tooltip — Hover the "Flexible" tag on a class to see what it means without having to guess.

2 Attendee
The customer-facing attendee view — schedules and class details as your members see them.
Capabilities:
Opens on today — Attendee now lands on the current week and current day the moment you enter, no manual navigation needed.
Current-week scope — Schedules shown reflect the current week only, matching what customers see in their own app.
Consistent look — Attendee now uses the same tables, filters, and toolbars as the rest of admin, so the module feels familiar the first time you open it.

3 Staff & shift
The shift management module for owners and admins.
Capabilities:
Time-off blocks shifts — You can't schedule a shift on a day where a staff member has an approved time-off request, so the roster stays accurate.

4 Pay rates & Payroll
Instructor pay rates and payroll runs for owners.
Capabilities:
Default rate + per-session overrides — Every instructor has a default pay rate; you can add per-class and per-private-session rates on top when a specific session pays differently.
Payroll uses the latest rates — Payroll runs pick up the current pay rate configuration, including recent per-class and per-private-session changes, so numbers are always current.

5 Customer
The customer list, profile, and follow-ups tab.
Capabilities:
Sticky profile tabs — Tabs stay fixed at the top while scrolling a long customer profile, so you can jump between Plan, Bookings, Follow-ups, Details, and other tabs at any scroll depth.
Stage rules side panel — The "why this stage" explanation opens in a right-slide side panel instead of a clipped tooltip, matching the create-customer flow from POS.
Richer sample customers — Sample data covers every lifecycle stage (Lead, Trialist, Active, Loyal, Churned, and more) so you can test filters and status transitions in one demo session.
Lifecycle filter — Filter the customer list by lifecycle stage right from the toolbar.
Staff & shift layout — Customer module now shares the same page layout as Staff & shift so navigation between the two feels the same.
Table breathing room — Added left/right padding around the customer table so rows sit flush with the page chrome, matching every other list.
One table for follow-up tasks — Open and closed follow-up tasks now share one table with a status column, instead of two separate lists.
Correct follow-up column names — Follow-ups table headers now accurately reflect what's in each column.
Follow-ups empty state centered — When there are no tasks, the message sits in the middle of the tab, not glued to the top.
Total count on Follow-ups — Follow-ups tab shows "Total N tasks" like the Bookings, Payments, and Referrals tabs.
Log-enquiry side panel — Logging an enquiry opens as a right-slide panel matching the POS create-customer flow, with a full-width Assign-to picker.

6 Settings — Lead lifecycle
The Settings tab for customer sources and follow-up stages.
Capabilities:
Cleaner page header — Removed the verbose description at the top; the page opens straight to the editable lists.
Add-source / add-stage modal — Creating a customer source or follow-up stage now opens the same modal shape as adding a tax rate, so every editable-list module in Settings works the same way.
Consistent delete confirmations — Deleting a customer source or follow-up stage now uses the same confirmation dialog as the rest of the app.

7 Dashboard
The owner and admin dashboard.
Capabilities:
"Leads to follow up" empty state centered — When there are no leads to follow up, the message sits in the middle of the widget instead of the top.

8 AI Agent
The AI assistant for admins — general chat, migrate data, studio setup.
Capabilities:
Floating trigger — Open the AI Agent from a floating tile in the bottom-right of every admin screen; one-line label on hover.
Every customer searchable — Fixed an issue where the AI Agent couldn't find some existing customers (e.g. Ava Wright) even though they were in the studio data.
Sidebar entry — Sidebar now shows a shortcut to the AI Agent alongside the floating trigger.

9 Retail (preview)
The upcoming Retail / Inventory module for physical products (apparel, supplements, equipment, and more) — visual preview only for this update.
Capabilities:
Menu entry — New "Retail" sub-item under Products & pricing so you can see where it will live.
List page preview — The list page shows the future layout: product image, name, SKU, category, price, stock, and status, with a floating bulk-action bar. Buttons and filters are visual only for now.
Implementation plan finalized — The full plan for stock tracking, POS integration, customer portal shop, and reports is locked in and ready to build.

General updates
Every side-menu action in the three-dot menu — Actions that live in the side menu (archive, deactivate, recover, delete) are also accessible from the three-dot menu on each row across every admin module, so you can act without leaving the row.
Bulk-action bar fits all buttons — When multiple statuses are selected, the floating action bar auto-sizes to fit every button (Archive, Reactivate, Recover, Delete) instead of clipping the last one.
